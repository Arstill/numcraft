## 1. Что оставить
1. Деплой-обвязку Coze (`main.py`, `scripts/`, `.coze`): HTTP `/run`, `/stream_run`, OpenAI-совместимый `/v1/chat/completions`.
2. LangGraph как оркестратор (граф и агент), но с новым состоянием.
3. Конфиг LLM `config/agent_llm_config.json` (OpenAI-совместимый endpoint) с новым русским системным промптом.

## 2. Что упростить или убрать
- Убрать генерацию траекторий, «оптимизацию» G-кода, фиктивные проверки столкновений. Траектории и симуляция остаются в HSMWorks.
- Убрать 5 псевдоагентов. LLM не должна выдумывать цифры: **все числа (S, F, ap, ae, глубины, циклы) считает детерминированный код**, LLM только извлекает данные и поясняет.
- Привязаться к одному станку (Haas VF-2) и 4 материалам. Профиль станка и библиотека инструмента вынесены в YAML и правятся без кода.

## 4. Организация агентов

```
вход (текст / STEP / PDF / JSON)
        │
   [intake] детерминированные парсеры ──► Part (pydantic)
        │            └─ при пробелах: LLM-извлечение (опционально)
   [plan]  planner + cutting + strategies (без LLM, воспроизводимо)
        │
   [risks] правила рисков
        │
   [review] LLM-рецензент (опционально): комментарий технолога, вопросы к недостающим данным
        │
   [render] техкарта MD/JSON + черновик G-кода
```

- **Граф** (`graphs/graph.py`) — пакетная обработка: одна деталь на входе, техкарта на выходе.
- **Чат-агент** (`agents/agent.py`) — один агент «Технолог» с инструментами `plan_part`, `analyze_step`, `analyze_drawing`, `cutting_data`. Он уточняет недостающее (материал, допуск, сторона), вызывает инструменты и пересказывает результат. Своих режимов агент не придумывает.
- Ядро `numcraft` работает и без LLM: CLI `python -m numcraft …`.

## 5. Объём MVP
2.5D–3-осевые детали из 6061/7075/стали 45/1045 на Haas VF-2: торцовка, наружный контур, карманы, пазы, отверстия (центровка, сверление, развёртывание, расточка спиралью), резьбы (метчик или фреза), фаски. 3D-поверхности распознаются и получают черновые и чистовые стратегии без расчёта траектории.
